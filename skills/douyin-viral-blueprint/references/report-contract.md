# report.json 契约

`check.mjs --contract` 会把这份清单打成可读格式输出。写之前先读一遍，交付时机器会逐条核。

## 顶层

```json
{
  "已看": [1, 2],
  "一句话结论": "写给要拍这条的人看，10–200 字",
  "依据":   { "画面": [], "口播": [], "评论": [], "数据": [] },
  "过程":   [ "4–8 步" ],
  "判断":   [ "八项", "…" ],
  "结构":   [ { "起始秒": 0, "段名": "", "概括": "" } ],
  "高亮":   [ { "起秒": 12, "止秒": null, "角色": "", "为什么": "" } ],
  "口播总结": [ "3–6 条" ],
  "评估":   { "六轴": {}, "指标": {}, "评论簇": [], "解读": {}, "该学的": [], "别学的": [], "下次怎么拍": [], "待验假设": [] },
  "维度":   { "话题/行业": [], "目标观众": [] },
  "缺口":   []
}
```

## 已看（拼图张号，自报）

```json
"已看": [1, 2]
```

打开看过哪几张拼图，就写哪几个张号。`check` 用它做两件事：

1. 有拼图却一张都没看过 → 待补（至少看 2 张，不足 2 张按实际数量）
2. 依据里引用的格号（如 `拼图-02.jpg 第 6 格`）必须来自已看的张 → 没看过就引用，判待补

> 这是**自报**，没有工具帮你记。看过就是看过，别为了让校验过去而填没看过的张号。

## 过程（4–8 步）

一步只推一件事，写成「因为 X → 所以 Y」，X 用指针不用数值。少于 4 步或多于 8 步都判待补。

## 判断八项（缺一项判待补）

```
赛道 / 形态 / 特点 / 人群 / 开场 / 结尾 / 选题位 / 论点
```

每条 `{ 项, 评价, 结论, 依据[] }`。

- `评价` 三档：`好` = 可借鉴其结构或表达方法，须用自己的素材改写；`警示` = 搬用会出事或不可迁移；`信息` = 中性事实判断
- 八项之外可另加至多 4 项（总数 ≤12）
- `开场` 只说前 30 秒；`结尾` 只说最后 60 秒
- `选题位` = 这条在它那个话题池里补了谁的空缺，不是「讲了什么」
- 每项都要给 `依据[]`，空着会被提醒；指针写从 card 根开始的完整路径

## 六轴与指标（0–10 整数，不许 null）

| 组 | 键名 |
|:--|:--|
| 六轴 | `涨粉力` `变现力` `传播力` `收藏力` `互动力` `长尾力` |
| 指标 | `语速` `口播覆盖率` `切镜每分钟` `首句秒` `藏赞比` `评赞比` `转赞比` `长尾天数` |

- 六轴是**综合指数**，不许单凭一两个指标认定
- 指标分打的是「对这个账号的可执行程度」，不是绝对值好坏
- 没底座的指标写 `null`（六轴不准 null，指标允许）

## 结构（2–8 段）

- `card.视频.章节` 有 ≥2 段时**交空数组**，分段以平台为准
- 自拟时：首段 `起始秒: 0`，相邻至少隔 15 秒，段名 2–6 字，概括 4–40 字
- 结构要铺满全片；高亮只标值得停下的句子，两份不许互相抄

## 高亮（4–8 处，至少 2 类角色）

- `起秒` 必须取 `card.口播稿[i].t` 的真实值（±2 秒内要能对上某句）
- `角色` 自己起，2–6 字，回答「这句起什么作用」（`开场钩子` `转折句` `情绪顶点`）；不许写修辞手法名，不许几条全用同一个名
- 盖住的句子不超过全稿三成 —— 挑句子，别划段落
- **短稿按实际可标数量**：稿子只有 2–3 句时，下限自动降到句数（`min(4, 句数)`），覆盖率豁免不生效
- 无口播时可空数组
- `起秒` 落在片尾之后、或对不上任何一句（±2 秒）会被提醒

## 口播总结（3–6 条）

- 每条 10–80 字，按讲述顺序（是地图不是排行榜）
- 说「作者讲了什么」（观点、步骤、结论、数字、例子），不是「怎么讲的」
- 有口播稿才必交；短稿下限同样是 `min(3, 句数)`

> **`card.口播判定` 存在时，说明这条是纯音乐 / 无有效口播**（`prepare` 已判定，`口播稿` 为空）。
> 此时高亮与口播总结都交空数组，缺口里写「本条无有效口播 + 判定原因」，
> 不要写「未转写（缺 key）」—— 那是两回事。

## 评论簇（card 聚出 ≥2 簇时必须全覆盖）

```json
{ "簇": 1, "名": "问价格", "一句话": "观众在要购买链接，有明显购买意向" }
```

- `名` 2–6 字，回答「这簇在聊什么」；不许抄机器关键词，不许用「正向」「讨论」这类空词
- `一句话` 30 字内，只依据簇的代表句写
- 漏一簇判待补

## 依据指针（最容易写歪）

- 一律写**从 card 根开始的完整路径**：`视频.作者.粉丝`、`内容轴.语速`、`评论.聚类.分布`
- **不许写数值**：写了会被提醒（数字由报告实时渲染，重跑后会打架）
- **指针必须真实存在**：`check` 会走一遍 card 的字段树，指向不存在的字段会被揪出来
- 拼图格号只能来自**真打开看过**的张（直接打开 `拼图-0N.jpg`，再把张号写进 `已看`）
- 格号要在该拼图的 `帧从`–`帧到` 范围内，越界会被提醒

## 维度提炼

```json
{ "话题/行业": [{ "值": "低配电脑跑 AI 工具", "依据": ["视频.标题"] }],
  "目标观众": [{ "值": "预算有限的业余剪辑者", "依据": ["评论.聚类.簇"] }] }
```

- 每维 2–4 条，宁可少而准
- `话题/行业` 要能反复拍（自检：拿它当选题维度还能不能拍出 5 条不同的片子）
- `目标观众` 要「谁 + 什么处境」，不是裸身份词
- 三样不提：成片形态 / 运营动作 / 只出现一次的单片内容点

## 正文写法（机器会查）

`一句话结论` / `过程` / 判断的 `结论` / `口播总结` / `该学的` / `别学的` / `下次怎么拍` 这几处是给人读的，机器查三件事：

| 检查 | 判定 |
|:--|:--|
| 里头的数字正好等于 card 现值 | 提醒 —— 数字由报告渲染，改写字段路径 |
| 出现字段路径、内部组号、反引号英文键名 | 提醒 —— 翻成人话，指针留在 `依据` 里 |
| 出现「（修正：前一步有误）」这类自我修正括注 | **待补** —— 哪步错就直接改写那步 |

## 禁止的写法

| 反例 | 为什么 |
|:--|:--|
| 「相比另一条 / 平台均值 / 行业经验」 | 手上只有这一条的视频，横向比较是印象不是事实。要写进 `待验假设` |
| 「值得注意的是」「不仅…而且…」 | 填空件，一句一个主张 |
| 「（修正：前一步有误）」 | 交付里不留修正过程，哪步错就改写那步 |
| 「漏斗 / 水位 / 私域 / 归因 / 转化 / 资产 / 抓手 / 赋能 / 闭环 / 方法论 / 颗粒度」 | 术语堆砌，翻成人话 |
| 把统计数字复述一遍当分析 | 数字由报告渲染，你要写的是数字说明了什么 |
