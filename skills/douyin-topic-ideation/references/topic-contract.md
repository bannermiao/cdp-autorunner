# 选题契约

每批恰好 10 条。`topics.mjs save` 会逐条核对，不通过就退回「待补」，不入库。

## 字段

```json
{
  "主题": "6–30 字，写具体角度，不写空泛标签",
  "看点": "10–90 字，目标观众为什么在意、能拿到什么",
  "内容定位": "泛选题 | 人设选题 | 转化选题",
  "创作路径": "晒过程 | 聊观点 | 讲故事 | 教知识",
  "爆款元素": ["成本"],
  "结构": [{ "段名": "2–8 字", "要点": "4–120 字" }]
}
```

外层再包一层来源，`save` 时会记到每条上：

```json
{
  "选题": [ ...10 条... ],
  "来源": {
    "报告": "7703502674125262099",
    "话题": "从 report.维度.话题/行业 取",
    "观众": "从 report.维度.目标观众 取",
    "依据": ["评论.聚类.簇", "评估.该学的"]
  }
}
```

## 配比（硬性）

| 内容定位 | 条数 | 这是什么 |
|:--|:--|:--|
| 泛选题 | 6 | 面向赛道的通用内容，不依赖作者身份 |
| 人设选题 | 2 | 靠「我」的经历、立场、判断立住的内容 |
| 转化选题 | 2 | 承接变现：带货、服务、引流 |

不是标题套路，是内容角色。人设与转化选题要靠账号档案里的 `专长/职业`、`变现途径` 立住；缺了先按素材推断并写进 `推断字段`，推断不出时 `save` 会给提醒（不拦入库），这时宁可把这两类换成泛选题。

## 爆款元素（1–2 个）

```
成本 / 人群 / 猎奇 / 对比 / 最差 / 头牌 / 怀旧 / 荷尔蒙
```

选真正适用的，不要为了填字段硬凑。

## 结构（3–5 段）

一段一件事，段名 2–8 字，要点 4–120 字。第一段就要抓住人，最后一段要收在可执行的东西上。

## 会被拦的写法

| 反例 | 判什么 |
|:--|:--|
| 「重拍这条」「改这条」「把这段换成」 | 待补 —— 选题要开新题，不是给原片续命 |
| 主题里有 赋能 / 抓手 / 闭环 / 打造 / 提升 / 全场景 / 干货 / 保姆级 / 颗粒度 / 方法论 | 待补 —— 换具体说法 |
| 主题 / 看点 / 结构里出现 落点 / 调性 / 收住 | 待补 —— 在说自己在干什么，直接写出那句台词 |
| 与库中已有主题重复（跨批次） | 待补 —— 换角度或改写 |
| 配比不是 6 / 2 / 2 | 待补 |
| 缺看点 | 待补 —— 看点是最容易被省掉的字段 |
| 主题不在 6–30 字 / 看点不在 10–90 字 | 待补 |
| 爆款元素不是 1–2 个，或不在名单里 | 待补 |
| 结构不在 3–5 段，段名不在 2–8 字，要点不在 4–120 字 | 待补 |

## 写作要求

- **主题写判断或结果，不写话题标签**。「礼包值不值：拆开算一遍」是主题，「聊聊礼包」不是
- **看点讲观众收益**，不是讲你打算怎么拍
- **结构要能兑现看点**：看点承诺算账，结构里就得有算账那一段
- 不许编造真实经历、案例、数据、效果；没有素材支撑就走泛选题
- 10 条之间不许只换标题或对象，观看体验必须真的不同

## 入库后的标记

只有两个，都不影响配比：

| 标记 | 作用 |
|:--|:--|
| **收藏**（★） | 挑「最近要拍的几条」。面板点星、或 `topics.mjs edit <id> 收藏=是` |
| **标签** | 自定义归类，如系列名；逗号分隔 |

删除是**直接删**，没有回收站：面板里有确认弹窗，CLI 是 `topics.mjs rm <id>`。
`save` 只做追加，永远不自动删旧选题。
